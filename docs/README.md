# Apixis 文档

Apixis 为 Python `asyncio` 应用提供事件处理和有状态图执行能力。要求 Python 3.12 或更高版本。

| 分类 | 读者 | 从这里开始 |
| --- | --- | --- |
| 使用文档 | 使用框架编写应用 | [快速开始](usage/quickstart.md)、[接口与使用指南](usage/README.md) |
| 开发文档 | 开发和维护框架 | [架构与设计取舍](development/README.md) |
| 测试文档 | 复现测试、核对测试与性能结果 | [测试指南](testing/README.md)、[性能结果](testing/performance/README.md) |
| 审查文档 | 跟踪代码审查、缺陷与修复 | [审查与修复记录](audits/README.md) |

应用开发可先阅读[生命周期](usage/lifecycle.md)，再按需要查阅[事件与等待](usage/event/README.md)、[处理器](usage/event/handlers.md)、[图执行](usage/graph/README.md)、[状态与命令](usage/graph/state.md)、[配置](usage/config/README.md)和[异常与日志](usage/utils/README.md)。

当前使用与开发指南描述工作区实现。带日期的测试和审查记录按正文标明的源码基线解释，历史测量不能代表当前版本的性能。

## 文档编写要求

项目文档按读者和用途分为上述四部分，编写和整理时遵循以下要求。

| 分类 | 位置 | 读者与内容 |
| --- | --- | --- |
| 使用文档 | `docs/usage/` | 面向 Apixis 使用者，指导公开接口如何使用，说明参数、返回结果、异常、生命周期及必要边界，并提供示例 |
| 开发文档 | `docs/development/` | 面向 Apixis 开发者，解释当前架构、职责归属、依赖方向、设计取舍与意图 |
| 测试文档 | `docs/testing/` | 保存测试复现指导、命令、环境与基线要求，以及测试结果汇总和性能测量报告 |
| 审查文档 | `docs/audits/` | 保存代码审查、一致性核对、缺陷分析及修复记录，区分发现时的行为与后续处理状态 |

### 内容与归属

- 根 README 保留安装、最小示例和文档入口。`src/README.md`、`tests/README.md` 只提供所在目录说明和相应入口。
- 使用文档以任务和公开接口组织，不要求使用者操作私有组件。实现细节及其理由放到开发文档，通过链接关联。
- 开发文档描述当前实现及其约束，说明每项设计解决的问题和代价。历史迁移与已完成修复归入审查记录，未实现的建议明确标注。
- 测试指导写明命令执行目录、依赖、源码基线、参数、结果位置及判定方式。测量报告写明日期、源码和驱动指纹、环境与规模，不将历史快照称为当前工作区。
- 审查记录保留问题的触发条件、证据、影响和处理状态。修复后补充结果，不把尚未处理或决定不修复的问题写成已经解决。
- 同一主题只维护一份主要说明，其他入口用链接引用。迁移文档时同步更新导航、相对路径、标题锚点和命令中的路径。
- 历史原始数据、脚本和 manifest 保持原样。现有 `docs/testing/performance/data/` 是测试报告的归档证据目录，`docs/audits/data/` 是审查证据目录。

### 对齐与验证

- 当前行为以既有代码、公开导出和可重复的执行结果为依据。接口示例应优先从 `apixis` 导入。
- 完整示例可独立运行并完成资源清理；片段写明需要的上下文。等待外部事件的示例无需额外发布事件。
- 修改文档后检查本地链接、锚点、示例语法与公开导入。涉及调用顺序或行为边界的示例，按对应场景实际验证。
- 仅文档任务不改运行时代码、docstring 或测试实现。发现它们仍需调整时，在审查记录中注明；已有测试结果只作为其对应基线的证据。
